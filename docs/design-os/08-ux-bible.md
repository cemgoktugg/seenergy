# E-Commerce Design Operating System

# Module 08 — UX Bible

## Premium Lingerie & Fashion Commerce Experience

---

# 1. Purpose

The UX Bible defines how customers move through the storefront.

It transforms individual pages and components into one coherent shopping experience.

The experience must optimize for:

* discovery
* confidence
* desire
* clarity
* low friction
* size confidence
* product understanding
* purchase completion
* mobile usability
* brand perception

The primary journey is:

```text
Discover
↓
Explore
↓
Understand
↓
Select
↓
Validate
↓
Add
↓
Review
↓
Continue
```

The customer should never wonder:

```text
Where am I?

What should I do next?

Which option did I select?

Will this size fit me?

Is this product available?

What happens if I click this?

Can I return this product?
```

---

# 2. UX Philosophy

The storefront should feel like a premium digital boutique rather than a marketplace.

The experience should be:

```text
Visual but usable

Premium but understandable

Editorial but commercial

Minimal but informative

Emotional but trustworthy

Fast but not rushed
```

Luxury should come from precision, not complexity.

---

# 3. Primary Customer Journeys

The storefront must support these journeys particularly well:

```text
Homepage → Category → Product → Cart

Homepage → Collection → Product → Cart

Search → Product → Cart

Category → Filter → Product → Cart

Campaign → Collection → Product → Cart

Product → Size Guide → Product → Cart

Product → Related Product → Product → Cart

Product → Wishlist → Return Later → Cart

Recently Viewed → Product → Cart
```

Every major page should support at least one of these paths.

---

# 4. UX Priority Hierarchy

When UX decisions conflict, prioritize:

```text
1. Product understanding
2. Size confidence
3. Purchase clarity
4. Mobile usability
5. Accessibility
6. Performance
7. Brand expression
8. Decorative interaction
```

Never sacrifice usability for visual novelty.

---

# PART I — HOMEPAGE EXPERIENCE

# 5. Homepage Purpose

The homepage must answer within seconds:

```text
What brand is this?

What does it sell?

What is new or important?

Where should I start shopping?

Why should I trust it?
```

The homepage is not a catalog dump.

It is a curated discovery experience.

---

# 6. Homepage Recommended Flow

Recommended premium structure:

```text
Announcement Bar

Header

Hero Campaign

Primary Category Discovery

New Arrivals

Editorial Brand Moment

Featured Collection

Best Sellers

Shop by Mood / Need

Editorial Lookbook

Product Rail

Brand / Material Story

Magazine Content

Trust Layer

Newsletter

Footer
```

Do not mechanically use every section.

Sections must earn their place.

---

# 7. Above-the-Fold Experience

Above the fold should contain:

```text
Brand
Primary campaign
Primary CTA
Global navigation
```

Avoid:

* multiple competing banners
* floating coupons
* immediate newsletter modal
* excessive badges
* autoplay sound
* large cookie UI covering the experience
* three or more competing CTAs

The first screen should feel calm.

---

# 8. Hero Interaction

Primary hero action should lead directly to a relevant commerce destination.

Example:

```text
Yeni Koleksiyon

Yumuşak dokular.
Güçlü bir his.

[Koleksiyonu keşfet]
```

Avoid generic:

```text
[Detay]
[Tıkla]
[Daha Fazla]
```

---

# 9. Homepage Category Discovery

Primary categories should be visually discoverable.

Example:

```text
Sütyen
Külot
Bralet
Gecelik
Pijama
Ev Giyimi
```

Use photography instead of excessive iconography.

Recommended:

```text
3–6 primary categories
```

Do not show every taxonomy branch on the homepage.

---

# 10. Homepage Product Discovery

Use product rails selectively.

Recommended:

```text

Çok Satanlar

Sizin İçin Seçtiklerimiz
```

Avoid stacking:

```text

Trending
Popular
Featured
Recommended
Best Seller
Most Viewed
Hot
```

when they largely contain the same products.

---

# 11. Homepage Editorial Rhythm

Alternate commercial and editorial sections.

Example:

```text
Hero

Category Discovery

Products

Editorial Image

Products

Collection Story

Lookbook

Trust
```

Avoid:

```text
Product Grid
Product Grid
Product Grid
Product Grid
```

A premium fashion storefront needs breathing room.

```text
How can I sort them?
```

# 14. Category Header

```text

Optional campaign image
```

Long SEO content may appear below the product experience.


```text

Balensiz ×

Tümünü temizle
```

Customers must be able to remove filters without reopening the complete filter interface.

Mobile should use a dedicated filter experience.

Flow:

```text

↓

Full-screen Filter Drawer

↓

Select multiple filters

↓

```

Do not close the filter interface after every selection.

---

# 19. Sorting UX

Sorting must remain simple.

Recommended:

```text

En yeniler

Çok satanlar

Fiyat: düşükten yükseğe

Fiyat: yüksekten düşüğe
```

Do not expose technical ranking terminology.

---

# 20. Product Grid Browsing

Customers should be able to scan products quickly.

The visual hierarchy should be:

```text
Image

Product name

Price

Color / variant information
```

Secondary data must not dominate.

---

# 21. Product Hover

Desktop hover may reveal:

```text
Second image

Quick Add

Wishlist

Available colors
```

But the card must remain fully understandable without hover.

---

# 22. Product Grid Continuity

When a customer opens a product and returns:

Preserve:

```text
Scroll position

Filters

Sorting

Loaded product count

Grid density
```

This is critical.

Do not return customers to the top of the category.

---

# 23. Load More vs Infinite Scroll

Preferred default:

```text
Daha fazla göster
```

Advantages:

* clearer progress
* footer remains reachable
* better orientation
* easier back navigation

Infinite scrolling may be used only when state restoration is excellent.

```text

A
B
C
D
```

```text
↓

75C

↓

↓

```

If the customer changes:

```text

```

Preserve C.

If C is unavailable:


Never silently change C to another cup.

Examples:

```text

Saved to wishlist

Quantity changed

```

---

# 75. Feedback Hierarchy

Use:

```text

↓
Toast
↓
Drawer
↓

```

---

# 76. Optimistic Interaction


# PART XIV — PERFORMANCE UX

# 84. Perceived Performance

Customers perceive speed through:

```text
Immediate response

Stable layout

Progress feedback

Image prioritization

Preserved context
```

A fast backend can still feel slow if the UI appears frozen.

---

# 85. Loading Strategy

Use:

```text
Skeleton → structured content

Spinner → small local action

Progress → multi-step task
```

Avoid full-page spinners for normal browsing.

---

# 86. Navigation Response

When navigation begins:

* provide immediate feedback
* preserve the current page until the next experience is ready where possible
* avoid white flashes
* preserve layout shell

# PART XVI — PERSONALIZATION READINESS

# 90. Personalization Principle

The frontend should be structurally ready for future personalization without depending on it.

Potential future signals:

```text
Recently viewed

Preferred categories

Preferred sizes

Favorite colors

Past purchases

Browsing behavior
```

Do not create invasive personalization.

---

# 91. Personalized Homepage

Future modules may support:

```text
Recently viewed

Continue shopping

Recommended for you

Back in stock

Your size available
```

These sections must disappear gracefully when data is unavailable.

---

# 92. Remembered Size

With explicit or reasonable customer consent, future functionality may remember:

```text

Alt giyim: M

Ev giyimi: M
```

Then PDP may show:

```text
Kayıtlı bedeniniz: 75C
```

Never auto-add or silently auto-select solely from remembered data.

# PART XVII — UX ANTI-PATTERNS

# 93. Avoid

Do not use:

```text
Immediate newsletter popup

Fake countdown timer

Fake stock urgency

Forced account creation

Autoplay sound

Excessive animation

Hidden return conditions

Preselected size

Unclear disabled buttons

Multiple sticky bars

Nested modals

Desktop-only hover interactions

Infinite carousels

Dark patterns

Misleading discounts

Fake reviews

Fake popularity
```

---

# 94. Premium UX Rule

Premium does not mean:

```text
More animation

More whitespace everywhere

Smaller typography

Hidden controls

Mysterious navigation

Low contrast

Long transitions
```

Premium means:

```text
Better hierarchy

Better photography

Better spacing

Better copy

Better interaction

Better feedback

Better consistency

Better restraint
```

# PART XIX — AI IMPLEMENTATION RULES

# 100. AI UX Rules

When an AI coding agent modifies the storefront, it must:

1. Identify the affected customer journey.
2. Preserve existing journey state.
3. Avoid introducing new friction.
4. Test mobile and desktop independently.
5. Preserve accessibility.
6. Preserve loading and error states.
7. Never auto-select product sizes.
8. Never create fake urgency.
9. Keep trust information accurate.
10. Use the smallest necessary interaction pattern.
11. Preserve product and filter state across navigation.
12. Validate commerce-critical state before purchase.
13. Protect performance.
14. Complete the relevant journey acceptance tests.

# 102. Final Principle

The best commerce UX should feel almost invisible.

Customers should spend their attention on:

```text
The product

The fit

The style

The purchase
```

—not on understanding the interface.

When uncertain:

```text
Reduce friction.

Preserve context.

Clarify the next action.

Make size selection safer.

Keep product information close.

Use honest feedback.

Design mobile intentionally.

Remove anything that does not help the customer.
```
